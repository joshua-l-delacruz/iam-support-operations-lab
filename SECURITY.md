# Security and data-handling policy

## Reporting

Use GitHub's private vulnerability reporting feature under **Security → Advisories → Report a vulnerability** for exploitable issues. Documentation corrections that contain only fictional, sanitized material can use the public issue form.

Never submit employer data, production screenshots, credentials, access tokens, tenant identifiers, real tickets, employee records, directory exports, or access-review evidence.

## Scope

This repository is a fictional IAM operations lab. Useful private reports include unsafe example automation, accidental real-world identifiers, guidance that could enable unauthorized access, prompt-injection weaknesses in the advisory assistant, or a mismatch between documented and enforced assistant boundaries.

The assistant is advisory-only and must not be represented as having production IAM connectors or authority to grant, revoke, or disable access.
